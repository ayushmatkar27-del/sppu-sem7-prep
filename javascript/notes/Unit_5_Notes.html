Q1. Explain Event and Event Handler with an example. What is the role of Event Handlers in JavaScript?
Appeared in: Nov/Dec 2022, May/Jun 2023, Nov/Dec 2023, May/Jun 2024, Nov/Dec 2024, May/Jun 2025, Nov/Dec 2025, May/Jun 2026
💡 Simple Analogy to Remember: An Event is like a doorbell ringing (something happened in the physical world). The Event Handler is the person who gets up, walks to the door, and opens it (the code that reacts to the event).

1. Definitions (2 Marks)

  • Event: An occurrence or state change that happens in the browser, usually initiated by a user action (clicking, typing, hovering, resizing) or the system (page finished loading, error occurred).
    • Examples: click, mouseover, keydown, load, submit, change.
  • Event Handler (or Event Listener): A JavaScript function written specifically to listen for and execute code in response to an event occurring on a specific HTML element.
  • Role of Event Handlers: They bridge static HTML pages and dynamic JavaScript logic. Without event handlers, a web page is completely static and cannot react to user clicks, keyboard typing, or form submissions!

2. Three Ways to Register an Event Handler (2 Marks)

  1. Inline HTML Attribute: <button onclick="handleClick()">Click</button> (Outdated).
  2. DOM Property Assignment: button.onclick = handleClick; (Only allows one handler).
  3. Modern W3C Standard: button.addEventListener("click", handleClick); (Allows multiple handlers).

3. Complete Working Program (2 Marks)

<!DOCTYPE html>
<html>
<body>
    <h2>Event & Event Handler Demonstration</h2>
    <button id="actionBtn">Hover Over Me or Click Me</button>
    <p id="statusMessage">Awaiting action...</p>

    <script>
        var btn = document.getElementById("actionBtn");
        var statusText = document.getElementById("statusMessage");

        // Event Handler 1: Responding to 'click' event
        btn.addEventListener("click", function(event) {
            statusText.innerHTML = "<b style='color:green;'>Button Click Event Handled!</b>";
            console.log("Event Type:", event.type, "Target:", event.target.tagName);
        });

        // Event Handler 2: Responding to 'mouseover' event
        btn.addEventListener("mouseover", function() {
            btn.style.backgroundColor = "#4f46e5";
            btn.style.color = "#ffffff";
        });

        // Event Handler 3: Responding to 'mouseout' event
        btn.addEventListener("mouseout", function() {
            btn.style.backgroundColor = "";
            btn.style.color = "";
        });
    </script>
</body>
</html>

Q2. Describe Netscape 4 Event Model in detail.
Appeared in: May/Jun 2024, Nov/Dec 2024, May/Jun 2025, Nov/Dec 2025
💡 Historical Context: In the late 1990s "Browser Wars", Microsoft Internet Explorer and Netscape Navigator had completely opposite ideas of how events should travel. Netscape invented Event Capturing (top-down), while IE invented Event Bubbling (bottom-up).

1. The Core Philosophy: Top-Down Event Capturing (2.5 Marks)

  • In the Netscape 4 Event Model, events originate at the highest level of the browser hierarchy (the window or document) and trickle DOWNWARDS through the element tree until they hit the intended target element.
  • This mechanism is called Event Capturing (Trickling).
  • Parent elements have the authority to intercept ("capture") an event before their child elements ever know it happened!

2. Key Methods of Netscape 4 Model (2 Marks)

Method Purpose
captureEvents(Event.TYPE) Instructs the window or document to intercept specific event types before lower elements.
releaseEvents(Event.TYPE) Stops intercepting that event type and lets it pass normally.
routeEvent(event) Passes the captured event down to the next lower element in the chain.

3. Example Syntax & Why It Was Replaced (1.5 Marks)

// Classic Netscape 4 Code Pattern
window.captureEvents(Event.CLICK);

window.onclick = function(e) {
    alert("Window intercepted the click event first!");
    // Route to child button
    return window.routeEvent(e);
};

Why It Became Obsolete: It was non-standard and incompatible with Microsoft IE. Later, W3C unified both Netscape's Capturing and IE's Bubbling into the unified DOM Level 2 Event Model.

Q3. Define JavaScript Object Model and explain four distinct object models used in JavaScript.
Appeared in: Nov/Dec 2022, May/Jun 2023, Nov/Dec 2023, May/Jun 2026

1. Definition of JavaScript Object Model (1.5 Marks)

The JavaScript Object Model is a structured architectural hierarchy that organizes all internal, document, and browser entities as interconnected objects with properties and methods, allowing scripts to programmatically read and modify the environment.

2. Four Distinct Object Models (4.5 Marks)

  1. 1. Core / Built-in Object Model (ECMAScript Objects):

    Standard language objects provided by JavaScript regardless of browser environment. Examples: Object, Array, Function, String, Number, Boolean, Math, Date, RegExp, Error.

  2. 2. Browser Object Model (BOM):

    Represents the web browser window and device environment. The top parent object is window. Includes: window.location, window.history, window.navigator, window.screen.

  3. 3. Document Object Model (DOM Level 0 / Legacy DOM):

    The early model introduced in Netscape 2/3. Organized elements strictly as arrays off the document object, such as document.forms[], document.images[], document.links[].

  4. 4. Standard W3C Document Object Model (DOM Level 1, 2, 3):

    Represents the HTML page as a complete hierarchical Node Tree where every single HTML tag, attribute, and text chunk is an accessible node object with standard APIs (getElementById, querySelector, addEventListener).

1. Events Explained (1.5 Marks)

  • onmouseover: Fires when the user moves the mouse cursor over an element.
  • onmouseout: Fires when the mouse leaves the element (used to reset color).
  • onfocus: Fires when an input element gains focus (user clicks or tabs into a text box).
  • onblur: Fires when the input element loses focus.

Q5. Describe Document properties and methods with their HTML relationship.
Appeared in: Nov/Dec 2022, May/Jun 2023, Nov/Dec 2023, May/Jun 2026

1. The HTML-Document Relationship (1.5 Marks)

The document object is the JavaScript representation of the root <html> page currently loaded in the browser window. When a browser loads HTML, it converts every tag into a node inside the document object. The document object is the sole entry point for accessing all HTML elements.

2. Common Document Properties (2 Marks)

Property HTML Relationship
document.title Reads or sets the text inside the <title> tag in the head.
document.URL Returns the complete URL address string of the document.
document.body Direct reference to the <body> HTML element.
document.forms Collection/array of all <form> tags on the page.
document.images Collection of all <img> tags on the page.
document.cookie Reads and writes key-value cookies associated with the page.

3. Common Document Methods (2.5 Marks)

Method Action
getElementById(id) Finds the single element whose id attribute matches.
getElementsByTagName(tag) Finds all elements matching HTML tag (e.g. "p", "div").
createElement(tag) Creates a brand new HTML element node in memory.
createTextNode(text) Creates a raw text node to place inside elements.
write(content) Writes raw text/HTML directly into the open page stream.

Q6. Differentiate between HTML and DHTML.
Appeared in: Nov/Dec 2022, May/Jun 2023, Nov/Dec 2023, May/Jun 2026

1. The Big Picture (1.5 Marks)

  • HTML (HyperText Markup Language): A standard markup language used to structure web content into headings, paragraphs, tables, and forms. HTML alone is completely static. Once rendered, it cannot change unless the user reloads the page.
  • DHTML (Dynamic HTML): Not a separate programming language! DHTML is a term describing the combination of HTML + CSS + JavaScript + DOM to create interactive, dynamic web pages that animate and change styles in real time without refreshing the page.

2. Master Differentiation Table (4.5 Marks)

Parameter HTML DHTML
Definition A static markup language for creating web pages. A combination of HTML, CSS, JavaScript, and DOM.
Interactivity Static. Pages do not change after being loaded. Dynamic. Pages react to user clicks, hovers, and inputs.
Server Load Higher: Any visual update requires reloading from server. Lower: Content updates instantly on client-side via JavaScript.
Animations / Effects Cannot animate or dynamically hide/show content. Supports animations, dropdown menus, modals, and tickers.
Database / Form Validation No built-in real-time validation without refresh. Validates user input instantly before submitting.
File Size & Complexity Simpler, lightweight, small code size. More complex, requires styling rules and script logic.

Q7. Explain DOM and CSS Elements with example. Write short note on DOM and HTML Elements.

1. The Relationship: DOM & CSS (2 Marks)

The Document Object Model (DOM) exposes every HTML element as an object with a style property. This style property contains all CSS attributes represented in camelCase (e.g., CSS background-color becomes JavaScript style.backgroundColor).

This allows scripts to dynamically change colors, fonts, visibility, and layout positions in real time!

2. CSS Property Naming Rule in JavaScript (1.5 Marks)

CSS Rule (Kebab-Case) DOM Property (CamelCase) Code Example
background-color element.style.backgroundColor box.style.backgroundColor = "blue";
font-size element.style.fontSize box.style.fontSize = "20px";
display: none element.style.display box.style.display = "none"; (Hides element)

Method A: getElementById("myId")

var title = document.getElementById("headerTitle");
title.textContent = "Updated Title";

Method B: querySelectorAll(".highlight")

Uses standard CSS selector syntax to retrieve a collection of all matching elements and loops through them:

var badges = document.querySelectorAll(".badge");
badges.forEach(function(badge) {
    badge.style.color = "red";
});

Q9. Describe how to create, insert and append nodes in DOM with an example program.
Appeared in: Nov/Dec 2024, May/Jun 2025, Nov/Dec 2025

1. Core Node Manipulation APIs (2 Marks)

  1. document.createElement("tagName"): Creates a new element node in browser memory (not yet visible on page).
  2. document.createTextNode("text"): Creates a text node to put inside the element.
  3. parent.appendChild(childNode): Attaches the newly created node as the last child of the parent.
  4. parent.insertBefore(newNode, existingNode): Inserts a new element before a specific sibling.
  5. parent.removeChild(childNode): Deletes an element from the DOM.

2. Complete Program: Dynamic To-Do List (4 Marks)

<!DOCTYPE html>
<html>
<body>
    <h2>DOM Node Creation & Appending Demo</h2>
    <input type="text" id="itemInput" placeholder="Enter new subject...">
    <button onclick="addItem()">Add to List</button>

    <ul id="subjectList">
        <li>JavaScript (Elective III)</li>
    </ul>

    <script>
        function addItem() {
            var input = document.getElementById("itemInput");
            var textValue = input.value.trim();

            if (textValue !== "") {
                // Step 1: Create a new <li> element node
                var newLi = document.createElement("li");

                // Step 2: Create a text node with the user text
                var textNode = document.createTextNode(textValue);

                // Step 3: Append text node into the <li>
                newLi.appendChild(textNode);

                // Step 4: Append the <li> into the parent <ul>
                var parentUl = document.getElementById("subjectList");
                parentUl.appendChild(newLi);

                // Clear input
                input.value = "";
            }
        }
    </script>
</body>
</html>

Q11. Explain DOM Level 2 Event Model (Event Flow: Capturing Phase & Bubbling Phase).
Appeared in: May/Jun 2024

1. The 3 Phases of W3C DOM Level 2 Event Flow (3 Marks)

The W3C DOM Level 2 standard unified Netscape and Microsoft models into a 3-phase lifecycle whenever an event occurs:

            Phase 1: CAPTURING (Top-Down)
[window] → [document] → [<body>] → [<div>]
                                       |
                   Phase 2: TARGET → [<button>] (Executed on Target)
                                       |
[window] ← [document] ← [<body>] ← [<div>]
             Phase 3: BUBBLING (Bottom-Up)
  1. Phase 1: Capturing Phase: The event travels downwards from the window object, through parent elements, down to the target.
  2. Phase 2: Target Phase: The event reaches the exact element that was clicked.
  3. Phase 3: Bubbling Phase: The event bubbles back upwards from the target through all its ancestor elements back to the window.

2. Controlling Bubbling vs Capturing via addEventListener (3 Marks)

The 3rd argument (boolean useCapture) controls whether the listener runs in Capturing or Bubbling phase:

// False (default) = Listens during BUBBLING Phase (Bottom-Up)
element.addEventListener("click", handler, false);

// True = Listens during CAPTURING Phase (Top-Down)
element.addEventListener("click", handler, true);

// Stopping event propagation to parent elements:
function handler(event) {
    event.stopPropagation(); // Halts bubbling immediately!
}
