Implementation #1. AWS CLI: Launch EC2 Instance with Security Group & Key Pair

Scripting automated provisioning of virtual machines (EC2) using the Amazon Web Services Command Line Interface (AWS CLI).

📘 1. Detailed Production / Structural Model (Full Architecture) 
# Step 1: Create a Security Group allowing SSH (Port 22) and HTTP (Port 80)
aws ec2 create-security-group \
    --group-name "WebserverSG" \
    --description "Security group for web server" \
    --vpc-id "vpc-0a1b2c3d4e5f6g7h8"

# Step 2: Add Ingress Firewall Rules
aws ec2 authorize-security-group-ingress \
    --group-name "WebserverSG" \
    --protocol tcp --port 22 --cidr 0.0.0.0/0

aws ec2 authorize-security-group-ingress \
    --group-name "WebserverSG" \
    --protocol tcp --port 80 --cidr 0.0.0.0/0

# Step 3: Launch Amazon EC2 Instance
aws ec2 run-instances \
    --image-id ami-0c55b159cbfafe1f0 \
    --count 1 \
    --instance-type t2.micro \
    --key-name "my-sppu-key" \
    --security-groups "WebserverSG" \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=SPPU-WebServer}]'
Technical Concepts & Sizing Notes:
  • t2.micro provides 1 vCPU and 1 GiB RAM (AWS Free Tier eligible).
  • Security Groups act as stateful firewalls at the hypervisor network interface layer.
⚡ 2. Exam Short Form (Super Simple & Short — Memorize & Write in 2 Minutes) 
# --- EXAM SHORT FORM (AWS EC2 Launch CLI) ---
aws ec2 run-instances \
    --image-id ami-12345678 \
    --instance-type t2.micro \
    --key-name mykey \
    --security-groups my-sg

Implementation #2. Amazon EBS Snapshot Creation via CLI & Python Boto3

Automating point-in-time incremental backups of Amazon Elastic Block Store (EBS) volumes attached to instances.

📘 1. Detailed Production / Structural Model (Full Architecture) 
# Method 1: Using AWS CLI command
aws ec2 create-snapshot \
    --volume-id vol-0123456789abcdef0 \
    --description "Automated daily backup of root production volume" \
    --tag-specifications 'ResourceType=snapshot,Tags=[{Key=Environment,Value=Production}]'

# Method 2: Python Script using AWS Boto3 SDK
import boto3

ec2_client = boto3.client('ec2', region_name='ap-south-1')

def backup_volume(vol_id):
    response = ec2_client.create_snapshot(
        VolumeId=vol_id,
        Description='Daily automated backup via Python Boto3',
        TagSpecifications=[{
            'ResourceType': 'snapshot',
            'Tags': [{'Key': 'CreatedBy', 'Value': 'BackupScript'}]
        }]
    )
    print("Snapshot created successfully. Snapshot ID:", response['SnapshotId'])
    return response['SnapshotId']

# backup_volume('vol-0123456789abcdef0')
Technical Concepts & Sizing Notes:
  • Snapshots are stored in Amazon S3 for 11 9's durability.
  • Subsequent snapshots are incremental—only changed blocks since the previous snapshot are billed.
⚡ 2. Exam Short Form (Super Simple & Short — Memorize & Write in 2 Minutes) 
# --- EXAM SHORT FORM (AWS CLI Snapshot) ---
aws ec2 create-snapshot \
    --volume-id vol-0a1b2c3d \
    --description "Exam Backup Snapshot"

Implementation #3. Google App Engine (GAE) Deployment Configuration (app.yaml)

The YAML descriptor file (`app.yaml`) configuring runtime environment, URL routing handlers, and autoscaling thresholds for Google App Engine applications.

📘 1. Detailed Production / Structural Model (Full Architecture) 
# app.yaml - Google App Engine Standard Environment Configuration
runtime: python39
instance_class: F2

# Environment variables accessible in application code
env_variables:
  ENV_TYPE: 'production'
  DATABASE_URL: 'cloudsql-proxy-connection-string'

# Routing Handlers for Static Files & Dynamic App
handlers:
  # Static assets (images, css, js) served directly from GAE CDN edge
  - url: /static
    static_dir: static/

  # Dynamic script handler routing to WSGI/ASGI app entrypoint
  - url: /.*
    script: auto
    secure: always # Forces HTTPS redirect

# Automatic Scaling Configuration
automatic_scaling:
  min_idle_instances: 1
  max_idle_instances: 5
  min_pending_latency: 30ms
  max_pending_latency: automatic
  target_cpu_utilization: 0.65
Technical Concepts & Sizing Notes:
  • Deploying is executed via a single command: gcloud app deploy app.yaml.
  • secure: always automatically enforces TLS/HTTPS encryption.
⚡ 2. Exam Short Form (Super Simple & Short — Memorize & Write in 2 Minutes) 
# --- EXAM SHORT FORM (app.yaml - 6 Lines) ---
runtime: python39
instance_class: F1
handlers:
  - url: /.*
    script: auto
    secure: always
