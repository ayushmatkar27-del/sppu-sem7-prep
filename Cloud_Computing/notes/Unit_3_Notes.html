Q1. Explain Hardware Level Virtualization: Compare Full Virtualization vs Para-Virtualization and Type-1 vs Type-2 Hypervisors.

1. Full Virtualization vs Para-Virtualization

FeatureFull VirtualizationPara-Virtualization
Guest OS ModificationNo modification required. Unmodified guest OS runs completely unaware of virtualization.Guest OS kernel must be modified to replace non-virtualizable instructions with hypercalls.
Hardware EmulationComplete hardware emulation using binary translation or hardware-assisted virtualization (Intel VT-x / AMD-V).No hardware emulation; direct communication between modified guest OS and hypervisor.
Performance OverheadHigher virtualization overhead due to traps and binary emulation.Near-native performance with significantly lower CPU overhead.
Portability & OS SupportHigh; supports proprietary closed-source OS (e.g., Windows, legacy kernels).Limited to open-source operating systems whose kernels can be recompiled (e.g., Linux Xen).
Industry ExamplesVMware ESXi, Microsoft Hyper-V, KVM with VT-x.Xen Para-virtualization, early VMware VMI.

2. Type-1 (Bare-Metal) vs Type-2 (Hosted) Hypervisors

  • Type-1 (Bare-Metal Hypervisor): Installs directly on the bare physical server hardware without underlying host OS. High performance, enterprise reliability, and strict security isolation (Examples: VMware ESXi, Citrix Hypervisor, KVM).
  • Type-2 (Hosted Hypervisor): Runs as an application layer on top of a conventional host operating system (e.g., Windows or Linux). Slower performance due to double OS translation, primarily used for software development and desktop testing (Examples: VMware Workstation, Oracle VirtualBox).

Q2. Explain Virtualization of CPU, Memory, Storage, and I/O / Network.
Appeared In: May 2023, May 2024, May 2025, May 2026, Nov 2022, Nov 2023, Nov 2024, Nov 2025
Cloud Computing Exam Strategy: Draw neat layered architectural diagrams, clearly differentiate virtualization and platform layers, and state enterprise cloud use cases.

Virtualization Subsystems

  1. CPU Virtualization: Involves sharing physical CPU cores among multiple virtual machines using time-slicing and hardware virtualization extensions (Intel VT-x/AMD-V). Privileged sensitive instructions executed by the guest OS are intercepted and safely emulated by the hypervisor without crashing the host CPU.
  2. Memory Virtualization: Decouples physical host memory from virtual guest memory. Introduces three tiers of addresses: Virtual Memory $\to$ Guest Physical Memory $\to$ Host Physical Memory. Managed via Shadow Page Tables (SPT) or hardware-assisted Extended Page Tables (EPT / Nested Paging).
  3. Storage Virtualization: Pools multiple physical storage drives (SAN, NAS, DAS) into a unified logical storage pool presented to VMs as virtual disks (e.g., `.vmdk`, `.vhdx`). Enables snapshotting, thin provisioning, and dynamic volume expansion.
  4. Network Virtualization (VLAN / SDN): Creates isolated virtual software-defined networks running on top of shared physical routers and switches. Hypervisors use Virtual Switches (vSwitch) to route traffic between co-located VMs without hitting physical cables.

Q3. Explain Virtual Clusters and Cloud Resource Management with Live VM Migration.
Appeared In: May 2023, May 2024, May 2025, Nov 2022, Nov 2023, Nov 2024

1. Virtual Clusters Concept

A virtual cluster is a collection of interconnected virtual machines dynamically provisioned over physical server nodes across a data center. Unlike physical clusters, virtual clusters can be resized, cloned, or destroyed on-demand according to varying computational workloads without re-cabling.

2. Live VM Migration Mechanism

Live migration transfers an active, running virtual machine from one physical server to another with zero visible downtime to end users:

  1. Pre-Migration: Destination host reserves necessary CPU and RAM resources.
  2. Iterative Pre-Copy: Hypervisor copies all memory pages to the destination host while the VM continues running on the source. Dirty pages modified during transfer are flagged and re-sent iteratively.
  3. Stop-and-Copy: VM is suspended for a few milliseconds; remaining dirty pages and CPU register states are transferred.
  4. Resume: VM resumes execution on the new host, and network ARP packets broadcast the new MAC-to-port mapping.
